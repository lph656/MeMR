## 2. Gate implementations

The core gate logic is in `experiments/prompt_r3_c2/gate_probe.py`.

### 2.1 Shared score computation

Given query embedding `q`, metadata embeddings `m_t`, and task keys `k_t`:

- Normalize:
  - `q_n = normalize(q)`
  - `m_n = normalize(m)`
  - `k_n = normalize(k)`
- Cosines:
  - `cos(q, m_t)`
  - `cos(q, k_t)`
  - `cos(m_t, k_t)`
- Dynamic task embedding:
  - `d_t = alpha_t * m_t + (1 - alpha_t) * k_t`
- Routing score:
  - `s_t = softmax_scale * cos(q, d_t)`

Code path:
- `_compute_alpha(...)`
- `_compute_scores(...)`
- `softmax_scale = key_encoder.config.softmax_match_scale`

### 2.2 `current`

- Formula: `alpha = sigmoid(cos(q, m))`
- Implementation: direct sigmoid on cosine similarity between query and metadata embedding.
- Trainable? No.
- Temperature/bias? No.
- Re-training? No, inference only.

### 2.3 `metadata_only`

- Formula: `alpha = 1`
- Meaning: use metadata embedding only, ignore task key.
- Trainable? No.
- Temperature/bias? No.
- Re-training? No, inference only.

### 2.4 `temperature`

- Formula: `alpha = sigmoid((cos(q, m) + bias) / temperature)`
- Parameters:
  - `temperature = softplus(raw_temperature) + 1e-4`
  - initialized with `--temperature-init 1.0`
  - `bias` initialized to `0.0`
- MLP? No.
- Re-training? Yes. The gate parameter(s) are trained on the same train/dev split used by `prompt_r3_c2`.
- Training details:
  - optimizer: AdamW
  - epochs: 8
  - batch size: 32
  - lr: `5e-4`
  - best checkpoint selected by dev top-1 accuracy
- Saved artifacts:
  - `experiments/prompt_r3_c2/outputs/temperature/gate_state.pt`
  - `experiments/prompt_r3_c2/outputs/temperature/train_history.json`
  - `experiments/prompt_r3_c2/outputs/temperature/best_dev.json`

### 2.5 `learnable_mlp`

- Formula: `alpha = sigmoid(MLP(features))`
- Features (`6-dim`):
  1. `cos(q, m)`
  2. `cos(q, k)`
  3. `cos(m, k)`
  4. `||q - m||`
  5. `||q - k||`
  6. `||m - k||`
- MLP:
  - `Linear(6 -> hidden_size)`
  - `GELU`
  - `Linear(hidden_size -> 1)`
  - default `hidden_size = 32`
- Re-training? Yes, same training protocol as `temperature`.
- Saved artifacts:
  - `experiments/prompt_r3_c2/outputs/learnable_mlp/gate_state.pt`
  - `experiments/prompt_r3_c2/outputs/learnable_mlp/train_history.json`
  - `experiments/prompt_r3_c2/outputs/learnable_mlp/best_dev.json`

## 3. Cold-start setup

Source: `experiments/reviewer_0629/run_cold_start_eval.py`

### 3.1 Held-out department

- Held-out task: `zhongliuke`
- Seen tasks:
  - `neike`
  - `waike`
  - `erke`
  - `fuchanke`
  - `nanke`

### 3.2 How `metadata_init` and `random_init` are built

- `metadata_init`:
  - uses the held-out department metadata embedding from `metadata_embeddings/keshi_meta_embeddings.pt`
- `random_init`:
  - a random vector sampled with fixed seed `20260629`
  - rescaled to the mean norm of the seen task keys
- `mean_seen_init`:
  - mean of seen task keys
  - useful as a reference heuristic, but not the main cold-start baseline

### 3.3 What is trained

- No new task model is trained for the cold-start evaluation.
- The evaluation directly compares the routing weight assigned to the newly introduced task when one extra candidate key is appended to the seen-task set.

### 3.4 Metrics

For each evaluation sample:

- Compute extended weights over `seen_count + 1` tasks.
- `Top-1-N` = fraction where the held-out task is rank-1.
- `Top-3-N` = fraction where the held-out task is in top-3.
- `AvgW-N` = average weight assigned to the held-out task.

Implementation:
- `compute_extended_weights(...)`
- `torch.softmax(cos_sim * softmax_match_scale, dim=-1)`

## 4. Metadata corruption conditions

Source: `metadata_robustness_experiments/metadata_perturbation.py`

The perturbations operate on non-identifier metadata fields only. Identifiers such as department names are excluded.

### 4.1 `Missing-50`

- Implementation: `_missing_50(...)`
- Effect: keep about 50% of text units in each field.
- Mechanism:
  - split each field into text units
  - randomly keep half of them
  - if a field becomes empty, force one fallback unit to remain

### 4.2 `Noisy-30`

- Implementation: `_replace_ratio(..., replace_ratio=0.3)`
- Effect: replace about 30% of units in each field with units from other tasks.
- Mechanism:
  - draw replacement units from a cross-task pool
  - prefer same field but different task
  - if unavailable, fall back to any other task

### 4.3 `Stale-C` / `stale_coarse`

- Implementation: `_stale_coarse(...)`
- Effect: coarsen metadata aggressively.
- Mechanism:
  - for `description`, keep only the first unit
  - for other fields, keep only the first unit if the field originally has one unit; otherwise drop the field content

### 4.4 `InstMix-40` / `institution_mix_40`

- Implementation: `_replace_ratio(..., replace_ratio=0.4, forced_source_task_id=neighbor_task_id)`
- Effect: replace about 40% of units with units from the most similar task.
- Similarity selection:
  - first tries cosine similarity of metadata embeddings
  - if needed, falls back to lexical Jaccard similarity
- Replacement source:
  - the nearest neighbor task under the similarity mapping

## 5. Noisy-label training

Source:
- `experiments/reviewer_0629/make_noisy_label_dataset.py`
- `experiments/reviewer_0629/runbooks/terminal0_train_noisy_labels.sh`
- `experiments/reviewer_0629/outputs/noisy_labels_training/configs.json`

### 5.1 What is noisy

- This is **training-data label noise**, not test-time input noise.
- The script creates a new training dataset under:
  - `experiments/reviewer_0629/generated_datasets/noisy_labels_20/medical_consult`

### 5.2 How labels are perturbed

- `noise-ratio = 0.2`
- Cyclic reassignment across tasks:
  - take the first 20% of each task’s training records
  - move them to the next task in the task list
  - the last task wraps around to the first
- This is not random token corruption.
- It is a task-label / task-assignment corruption at the dataset construction level.

### 5.3 Training setup

- Trainer entry: `experiments/reviewer_0629/train_variant.py`
- Base model: `chinese-alpaca-plus-7b-hf`
- Tasks: `neike_waike_erke_fuchanke_nanke_zhongliuke`
- LoRA:
  - `r=4`
  - `lora_alpha=16`
  - `lora_dropout=0.1`
  - `target_modules=["q_proj", "v_proj"]`
- MPEFT:
  - `matching_loss_v2=True`
  - `meta_embeddings_path=./metadata_embeddings/keshi_meta_embeddings.pt`
- Training:
  - `num_train_epochs=4`
  - `per_device_train_batch_size=1`
  - `gradient_accumulation_steps=8`
  - `learning_rate=1e-4`
- Output checkpoint:
  - `experiments/reviewer_0629/outputs/noisy_labels_training/snapshots/task_5_zhongliuke_train_end_20260630_115350`

### 5.4 What do Clean / Del-10 / Swap-10 mean?

- In the saved routing summaries, `none`, `char_delete_10`, `char_swap_10` refer to **test-time input perturbations** applied during evaluation.
- They do **not** mean training-label noise levels.
- Therefore:
  - training is noisy-label training
  - evaluation additionally probes routing under perturbed inputs

## 6. Full weighted routing vs top-k routing

### 6.1 Implementation

Source:
- `experiments/reviewer_0629/common.py`
- `experiments/reviewer_0629/run_routing_diagnostics.py`
- `experiments/reviewer_0629/run_unseen_department_eval.py`

Mechanism:
- `full`: use the original routing weights as produced by the key encoder.
- `top1`, `top2`, `top3`:
  - call `constrain_weights(weights, top_k)`
  - keep only the top-k weights
  - zero out the rest
  - renormalize to sum to 1

The relevant function is:
- `patched_route_mode(key_encoder, top_k)`

### 6.2 Why generation metrics can be identical

The saved results show identical generation metrics across `full`, `top1`, `top2`, and `top3` for the same evaluation subset.
This can happen because:

- the underlying generation is deterministic
- the active adapter selection is already stable
- the constrained weight distribution may not change the final decoded tokens on this fixed subset
- the evaluation set may be insensitive to small changes in routing weights

Important caveat:
- The current evidence supports equivalence **on the fixed held-out subset only**.
- It does not prove universal equivalence for all data.

## 8. What is strictly supported vs what should be weakened

### 8.1 Strictly supported

- MeMR routing is non-trivial and measurable.
- Metadata initialization is clearly better than random initialization for cold-start routing.
- Held-out `zhongliuke` supports route-level unseen-department evaluation.
- Metadata corruption degrades routing, but moderate corruption still leaves usable routing.
- Noisy-label training does not destroy routing behavior.
- Full weighted routing and top-k routing are equivalent on the fixed held-out generation subset used here.

### 8.2 Should be weakened or avoided

- Do not claim `metadata_only` is universally better than the current gate.
  - The results are close; the evidence only supports comparable or slightly better routing on the tested subsets.
- Do not claim the learned gates substantially improve task matching.
  - `temperature` and `learnable_mlp` do not beat `metadata_only` in a robust way.
- Do not overclaim cold-start generalization from a single held-out department.
  - It is a valid held-out case study, not a leave-one-department-out average.
- Do not treat the identical generation metrics under `full/top-k` as proof that routing never matters.
  - It is evidence of stability on this subset only.
- Do not describe `Clean / Del-10 / Swap-10` in the noisy-label section as training-label ratios.
  - They are test-time input perturbations in the routing evaluation.

## 9. English technical note draft for the response letter

> We added a gate-level ablation study to directly compare the current sigmoid(cosine) gate, a metadata-only variant, a temperature-scaled gate, and a small learnable MLP gate. The results show that the metadata prior already provides a strong and stable routing signal, while the more parameterized gates do not deliver consistent gains on the fixed routing benchmarks. In the cold-start setting, metadata initialization clearly outperforms random initialization for the held-out department, supporting its role as a useful prior for new-task routing. We also find that moderate metadata corruption still leaves the router usable, noisy-label training does not collapse routing behavior, and full weighted routing is empirically comparable to top-k routing on the held-out generation subset. Accordingly, we keep the main claims conservative and only emphasize conclusions that are directly supported by the observed results.
